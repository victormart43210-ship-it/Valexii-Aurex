# KUSANAGI CL — Timestamp Reproduction & Clock Skew Audit

## Defect Summary
- **Symptom:** Live frontend reported "INVALID / FUTURE TIME" and "Railway connection: Unavailable" when connecting to Railway AUREX backend.
- **Root Cause Analysis:**
  1. Copilot PR #128 commit `e813138cc06204c90dec57ceb1150a7d93fa0ece` modified `evidenceFresh()` in `website/src/lib/aurex-api-schema.ts` from `t <= now + 60_000` to `t <= now` (0ms clock skew tolerance).
  2. In distributed cloud hosting (Railway backend vs Cloudflare/Lovable website serverless runtime), minor NTP drift or network latency of even 1-5 milliseconds caused `collectedAt` timestamps generated by Railway to be slightly ahead of `now` at evaluation time.
  3. Strict `t <= now` evaluation evaluated to `false`, invalidating fresh evidence link assertions in `capabilityBacked()` and causing capabilities to be stripped during health status resolution in `checkAurexService()`.

## Reproduction Test Case
- **Test File:** `website/src/components/timestamp-skew.test.ts`
- **Reproduction Result:**
  ```ts
  const now = Date.parse("2026-10-24T12:00:00.000Z");
  const drift500ms = { collectedAt: "2026-10-24T12:00:00.500Z" };
  // Under t <= now: RECEIVED FALSE (FAILED)
  // Under t <= now + 60_000: RECEIVED TRUE (PASSED)
  ```

## Applied Fix & Verification
- Restored `t <= now + 60_000` (+60s clock skew window) in `website/src/lib/aurex-api-schema.ts`.
- Genuinely future-dated evidence (> 60s ahead) remains strictly rejected (`evidenceFresh() -> false`).
- Stale evidence (> 7 days old) remains strictly rejected (`evidenceFresh() -> false`).
- Verified across all 165 Bun website tests.
