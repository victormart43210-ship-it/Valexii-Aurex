## Identity discipline

- **VALEXII.AI**: platform/organization; **BCXMET**: current public Android cybersecurity product; **XAELI**: assistant identity; **DISPATER.AI**: industrial direction; **XAITA.AI**: separate financial/market direction; **AUREX**: evidence/evaluation backend.
- `CoreGuard-Android` package names are historical build identifiers, not approved public marketing names.
- `AUREX/OX` website status must separate code proposals, local tests, published source, Railway live deployment and a verified owner-authenticated end-to-end handshake.
- **KUSANAGI OMEGA Hypothesis C:** human-reviewed, *synthetic-first* proof-gated invoice vs PO/ticket discrepancy design. GitHub draft PR #77 is design/plan, NOT a live finance engine. Never claim automated financial approvals or independently validated savings.
- **Fork provenance:** `cli` and `log-dog-android-sdk` have different upstream maintainers. Never attribute their implementations to VALEXII.AI or replace their project instructions with unrelated marketing.
- **Binary provenance:** a standalone DLL without verified source/build/signature is not a trusted security component.
- **Inert/empty projects:** avoid suggesting deployable features or integration where no code exists.
- GitHub repository descriptions are an **About metadata field**, independent of README content. The connected GitHub tool can edit files on accessible repositories but does **not** expose repository-metadata PATCH. Suggested descriptions must be set by a user/repository administrator using GitHub’s **About** editor.

## Verification and approval

For any README change, compare against current `main` and review an isolated pull request. The content must preserve license, security documentation and old implementation notes without promoting historical releases as current. Do not merge, deploy, alter DNS, change billing, distribute third-party binaries or disclose private repositories.
